== concept
### Counting ke 2 basic rules
- **Sum rule (OR)**: kaam A ya B (dono ek saath nahi) → ways = m + n.
- **Product rule (AND)**: pehle A phir B → ways = m × n.

### Permutation (order matter karta hai)
- n alag cheezon me se r ko **line me / order me** lagana: **ⁿPᵣ = n! / (n − r)! = n(n−1)(n−2)…(r terms)**.
- Saari n cheezein arrange: n!.
- **Repetition allowed** (with replacement) → nʳ (har position pe n choice).
- **Identical objects** ho (jaise MISSISSIPPI): n! / (n₁! n₂! …).
- **Circular arrangement**: (n − 1)! (necklace/garland jisme ulta-seedha same: (n−1)!/2).

### Combination (sirf group, order nahi)
- **ⁿCᵣ = n! / (r!(n − r)!)** = ⁿPᵣ / r! (kyunki ek group ke r! orders same gine jaate).
- ⁿCᵣ = ⁿCₙ₋ᵣ, ⁿC₀ = 1, ⁿCᵣ + ⁿCᵣ₋₁ = ⁿ⁺¹Cᵣ (Pascal).

### Kaunsa lagana hai — keywords
- "arrange, one after another, in order, positions, president/secretary, password" → **P**.
- "select, choose, committee, group, team, hand of cards" → **C**.
- "with replacement / repetition allowed" → nʳ.

### Is topic se aur kya puchha ja sakta hai
1. **3 cards with replacement**, order matter → 42³ = 74088.
2. **Kitne alag 3-card hands** (order nahi) → ⁴²C₃ = 68880 / 3! = 11480.
3. **5 log, 3 kursiyaan** → ⁵P₃ = 60. **Committee of 3 from 5** → ⁵C₃ = 10.
4. **"LEVEL" ke arrangements** → 5! / (2! 2!) = 30.
5. **6 log round table** → (6 − 1)! = 120.
6. **4-digit PIN, digits repeat allowed** → 10⁴; repeat nahi → ¹⁰P₄ = 5040.
== tips
- Pehle socho "order matter karta hai?" — yahi P vs C decide karta hai.
- Options me hamesha ek **trap** hota hai: yahan 1722 = 42 × 41 (sirf 2 cards) aur 6880 (zero chhoot gaya).

1. "One after the other", without replacement → order matter, repetition nahi → permutation.
2. 1st card: 42 tarike, 2nd: 41, 3rd: 40 (product rule).
3. ⁴²P₃ = 42 × 41 × 40 = 1722 × 40 = **68880**.

== hint
Rule: **kisi event/I-O ka intezaar → Waiting**, **sirf CPU chhina gaya (time slice / interrupt) → Ready**. I/O ke baad seedha Ready (A) ✗, time slice ke baad Waiting (C) ✗, interrupt ke baad Waiting (D) ✗. Sirf B possible.
== concept
### Process ke states (5-state model)
1. **New** — process ban raha hai.
2. **Ready** — memory me hai, CPU milne ka intezaar (ready queue).
3. **Running** — CPU pe instructions chal rahe hain.
4. **Waiting / Blocked** — kisi **event** ka intezaar (I/O complete, child terminate, semaphore signal).
5. **Terminated** — kaam khatam.

### Transitions (kab kya hota hai)
- New → Ready: **admitted** (long-term scheduler).
- Ready → Running: **dispatch** (short-term scheduler / dispatcher).
- Running → Ready: **preemption** — time quantum khatam (timer interrupt) ya higher-priority process aaya ya koi interrupt aaya.
- Running → Waiting: process ne **khud** I/O request ki, `wait()` kiya (child ke liye), semaphore pe block hua.
- Waiting → Ready: wo event ho gaya (I/O complete interrupt).
- Running → Terminated: `exit()` ya error.

### Kabhi nahi hone wale transitions
- **Waiting → Running** seedha ✗ (pehle Ready).
- **Ready → Waiting** ✗ (wait karne ke liye process ko chalna padta hai).
- **New → Running** ✗.

### Queues
- **Ready queue** (Ready state ke process), **device/I-O queues** (Waiting ke process, har device ki alag), **job queue**.

### Is topic se aur kya puchha ja sakta hai
1. "Which transition is **not** possible?" → Waiting→Running, Ready→Waiting.
2. "Timer interrupt aane pe running process kahan jaata hai?" → Ready.
3. "Suspended states" (7-state model): Ready-Suspend, Blocked-Suspend — process swap out (disk pe) hone pe; medium-term scheduler.
4. "Kaunsa scheduler Ready → Running karta hai?" → short-term (CPU) scheduler.
5. "Zombie vs orphan": zombie = child khatam par parent ne `wait()` nahi kiya; orphan = parent pehle khatam.
== tips
- Ek line yaad: **Event ka wait = Waiting, CPU ka wait = Ready.**
- "Could not occur" questions me har statement ko is rule se check karo.
== sol
- A. I/O request ke baad **ready** queue me ✗ — I/O request = event ka wait → Waiting (device queue). → **nahi ho sakta**.
- B. Child process bana ke uske terminate hone ka wait ✓ — `fork()` + `wait()` → Waiting. → ho sakta hai.
- C. Time slice khatam → **waiting** queue me ✗ — sirf CPU chhina, event ka wait nahi → Ready. → **nahi ho sakta**.
- D. Interrupt se hata kar **waiting** queue me ✗ — preemption → Ready. → **nahi ho sakta**.
Answer = A, C, D.

**Answer: (D) A, C and D only**
== refs

- William Stallings — Operating Systems: Internals and Design Principles, Sec 3.2 (Five-state and suspend models).

### Count-to-infinity
Link toot jaaye to A ka neighbour B purani table ke basis pe kehta "mere through 2 hops" → A use maan leta → dono ek doosre ki galat cost badhaate rehte (3, 4, 5, … ∞). Fix: **split horizon**, **poison reverse**, **hold-down timers**, max hop (RIP me 16 = infinity).

- 802.5 → Token Ring
- 802.11 → Wi-Fi (WLAN)
- **802.15 → WPAN**: 802.15.1 **Bluetooth**, 802.15.4 **Zigbee**

### MANET routing protocols

- **Proactive (table-driven)**: DSDV, OLSR.

**Little's law**: n = λ × W. Queue me average n = 20 process, arrival rate λ = 10 per second → W = n / λ = 20 / 10 = **2 seconds**.
== concept
### Little's formula
Kisi bhi stable queueing system (steady state) me:
**n = λ × W**
- **n** = system/queue me average processes (customers)
- **λ** = average arrival rate (per unit time)
- **W** = har process ka average waiting time (system me bitaya time)
Kyu sahi hai: ek process W time tak queue me rehta hai; is dauraan naye λ·W process aa chuke hote hain — wahi average queue length hai. Ye kisi bhi scheduling algorithm aur arrival distribution ke liye valid hai.

### CPU scheduling algorithms evaluate karne ke tarike (Galvin)
1. **Deterministic modeling** — ek fixed workload pe har algorithm ka exact waiting time (Gantt chart).
2. **Queueing models** — arrival aur service distributions se formulas (Little's law yahin).
3. **Simulation** — trace-driven ya random workload.
4. **Implementation** — asli OS me lagaakar dekhna.

### Is topic se aur kya puchha ja sakta hai
1. W = 3 s, λ = 7/s → n = 21 processes.
2. n = 14, W = 2 s → λ = 7 per second.
3. "Little's law kis scheduling pe depend karta hai?" → kisi pe nahi (general).
4. Server utilisation ρ = λ / μ (μ = service rate); ρ < 1 hona chahiye warna queue infinite.
== tips
- Units hamesha match: λ per second → W seconds; λ per minute → W minutes.
- Formula ulta karna aana chahiye: W = n/λ, λ = n/W.
== sol
W = n / λ = 20 / 10 = **2 seconds**.

**Answer: (B) 02 seconds**
== refs
- Galvin — Operating System Concepts, Sec 5.8 (Algorithm evaluation; 5.8.2 Queueing models, Little's formula).
- Leonard Kleinrock — Queueing Systems Vol. 1, Ch. 2 (Little's result).

== hint
Main memory ke block ko cache ki kis line me rakhna — is process ko **mapping** kehte hain (direct, associative, set-associative).
== concept
### Cache kyu
CPU fast, main memory slow. Cache = chhoti fast memory jisme recently/frequently used data. **Locality of reference** (temporal + spatial) ki wajah se kaam karta hai.

### Mapping (Morris Mano: "transformation of data from main memory to cache memory is referred to as a mapping process")
1. **Associative mapping**: koi bhi block kisi bhi line me. Address = tag + word. Sabse flexible, par saare tags parallel compare (costly CAM).
2. **Direct mapping**: block j → line (j mod m). Address = tag | index | word. Sasta, par conflict misses.
3. **Set-associative (k-way)**: lines ko sets me; block j → set (j mod sets), set ki kisi bhi line me. Beech ka raasta.

### Related terms
- **Hit ratio** h = hits / total accesses. **Average access time** = h·t_c + (1 − h)·(t_c + t_m) (ya h·t_c + (1−h)·t_m, question ke model pe depend).
- **Replacement**: LRU, FIFO, Random (direct me zarurat nahi).
- **Write policies**: write-through, write-back (dirty bit).

### Is topic se aur kya puchha ja sakta hai
1. 64 KB cache, 16 B block, 32-bit address, direct → lines = 4096 (12-bit index), offset 4, tag 16.
2. "Kaunsi mapping me replacement algorithm nahi chahiye?" → direct.
3. "Associative mapping me kaunsi memory?" → content addressable memory (CAM).
4. h = 0.9, t_c = 10 ns, t_m = 100 ns → 0.9·10 + 0.1·(110) = 20 ns (hierarchical model).
== tips
- Mano ki book ki definitions UGC NET me shabdashah aati hain — "mapping process" yaad rakho.
== sol
Main memory → cache data ke transformation/placement = **mapping**.

**Answer: (C) Mapping**
== refs
- M. Morris Mano — Computer System Architecture, Sec 12.6 (Cache memory: associative, direct, set-associative mapping; writing into cache).
- Hamacher — Computer Organization, Sec 8.6 (Mapping functions).

### Boolean algebra ke important laws
- **De Morgan**: (AB)′ = A′ + B′, (A + B)′ = A′B′.
- Involution: (A′)′ = A.
- Complement: A + A′ = 1, A·A′ = 0.
- Absorption: A + AB = A, A(A + B) = A.
- Distributive: A(B + C) = AB + AC, A + BC = (A + B)(A + C).

### SOP aur POS
- **SOP** (sum of products): product terms ka OR, jaise xy + x′z.
- **POS** (product of sums): sum terms ka AND.
- **Canonical / complete SOP** = har product term me **saare variables** → **minterms** ka sum (Σm). Missing variable v ko (v + v′) se multiply karke expand karo.
- **Canonical POS** = **maxterms** ka product (ΠM).
- n variables → 2ⁿ minterms. Σm(list) ka complement = Σm(baaki).

### Minterm number
x y z = 1 1 0 → m6. Yahan xyz = m7, xyz′ = m6, xy′z′ = m4 → A = Σm(4, 6, 7).

### Is topic se aur kya puchha ja sakta hai
1. Canonical POS of same A → ΠM(0, 1, 2, 3, 5).
2. "Complement of A" → Σm(0, 1, 2, 3, 5).
3. Simplify Σm(4, 6, 7) → x(y + z′) = xy + xz′ (K-map se).
4. "Number of minterms in canonical form of x + y (3 variables)" → 6.
== tips
- **Shortcut check**: x = 0 pe A = 0 → canonical form me koi x′ term nahi ho sakta. Isse (A), (B), (C) turant kat jaate.
== sol

2. xy = xy(z + z′) = xyz + xyz′.
3. xz′ = xz′(y + y′) = xyz′ + xy′z′.
4. Duplicates hatao: **xyz + xyz′ + xy′z′** = Σm(4, 6, 7).

**Answer: (D) xyz + xyz′ + xy′z′**

### Virtual memory (Morris Mano ki language)
- Programmer ko lagta hai bahut badi memory hai; asal me chhoti main memory + disk.
- **Address space** = program jo addresses generate karta hai = **virtual addresses** ka set (N).
- **Memory space** = main memory ki locations = **physical addresses** ka set (M), usually M < N.
- **Address mapping**: virtual → physical, memory **page table** se (pages ↔ blocks/frames).

### Paging vs Segmentation
- **Paging**: fixed-size pages; user ko dikhai nahi deta; internal fragmentation.
- **Segmentation**: variable-size logical units (code, data, stack, function); programmer ko dikhta; CPU **logical address = (segment, offset)**; external fragmentation. Segmented-paging dono milata.

### Cache organisations
- **Associative mapping** → content addressable memory (CAM), sabse fast/flexible.
- Direct, set-associative.

### Is topic se aur kya puchha ja sakta hai
1. Address space 2²⁰ words, memory 2¹⁵, page 1K → pages = 1024, blocks = 32, page table = 1024 entries.
2. "Logical address kaun generate karta?" → CPU. "Physical address kaun dekhta?" → memory unit.
3. "Segmentation se kaunsi fragmentation?" → external. Paging → internal.
4. "TLB kya hai?" → page table entries ka associative cache.
== tips
- Pair yaad: **Address space ↔ Virtual**, **Memory space ↔ Physical**.
== sol
A → IV (virtual), B → III (physical), C → I (associative mapping), D → II (logical address).

**Answer: (A) A-IV, B-III, C-I, D-II**
