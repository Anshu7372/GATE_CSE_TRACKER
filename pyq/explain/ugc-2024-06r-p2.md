== hint
I0 me A→.$B$ hai. $ pe GOTO karo → dot $ ke baad aa jaata hai, dot ab B ke aage hai, to B ki saari productions (aur unse A ki) closure me aa jaayengi. Items gin lo.
== concept
### LR(0) items, CLOSURE aur GOTO
- **Item** = production + dot, jaise A→α.β (dot batata hai kitna padh liya).
- **CLOSURE(I)**: agar I me A→α.Bβ hai (dot ke baad non-terminal B), to B ki har production B→.γ add karo. Yahi baar-baar karo jab tak naya item na aaye.
- **GOTO(I, X)**: I ke jin items me dot ke baad X hai, unme dot ko X ke aage khisakao, phir us set ka CLOSURE lo.

### Steps (yaad rakho)
1. Kernel items nikaalo (dot shift kiye hue).
2. Har kernel item me dot ke baad non-terminal dekho → uski productions .γ ke saath add.
3. Naye items me bhi yahi check (recursive productions jaise B→B,A ek hi baar add hoti hai).

### Is topic se aur kya puchha ja sakta hai
1. "I0 me kitne items?" → S'→.S type augmented + closure. Is grammar me I0 = {S→.A, A→.$B$, A→.id} = 3 items.
2. "GOTO(I0, id)" → {A→id.} = 1 item (reduce state).
3. "GOTO(I0, A)" → {S→A.} = 1 item.
4. "Kaunsa state shift-reduce conflict deta hai?" → jis state me A→α. (complete) aur B→β.aγ (terminal ke aage dot) dono hon aur LR(0)/SLR me a ∈ Follow(A).
5. "LR(0) me kitne states?" → canonical collection banao, har naya GOTO set ek state.
== tips
- Left-recursive production (B→B,A) closure me sirf ek baar likhte hain; repeat mat gino.
- Dot ke baad **terminal** ho to closure kuch add nahi karta.
== sol
I0 = CLOSURE({S→.A}) = {S→.A, A→.$B$, A→.id}.

GOTO(I0, $): kernel = A→$.B$
- Dot ke baad B → add B→.B,A aur B→.A
- B→.A me dot ke baad A → add A→.$B$ aur A→.id

Set = {A→$.B$, B→.B,A, B→.A, A→.$B$, A→.id} = **5 items**.

**Answer: (C) 5**
== refs
- Aho, Lam, Sethi, Ullman — Compilers (Dragon Book), Sec 4.6.2 (Items and the LR(0) automaton: CLOSURE, GOTO).

Pehle candidate keys nikaalo. D kisi FD ke right side me nahi hai → har key me D hoga. Phir dekho koi non-prime attribute key ke kisi **hisse** pe depend to nahi (partial dependency).
== concept
### Normal forms ki seedhi
- **1NF**: sab values atomic.
- **2NF**: 1NF + koi **partial dependency** nahi (non-prime attribute kisi key ke proper subset pe depend na kare).
- **3NF**: har non-trivial X→A me ya to X superkey ho, ya A prime ho (transitive dependency nahi).
- **BCNF**: har non-trivial X→A me X superkey.

### Candidate key kaise nikaalein
1. Jo attribute kisi RHS me nahi → zaroor key me (yahan D).
2. Jo sirf RHS me aata hai (LHS me kabhi nahi) → key me nahi (yahan G).
3. Bache attributes ke saath closure try karo.

### Is topic se aur kya puchha ja sakta hai
1. R(A,B,C,D) {AB→C, C→D} → key AB; C→D transitive → 2NF hai, 3NF nahi.
2. R(A,B,C) {AB→C, C→B} → keys AB, AC; sab prime → 3NF, par C→B me C superkey nahi → BCNF nahi.
3. "Prime attributes kaunse?" → kisi bhi candidate key ka hissa.
4. "Kitni candidate keys?" → equivalence chains (A→…→E→A) se ek key se doosri bana lo.
== tips
- Partial dependency check: **key ka ek tukda → non-prime** mile to turant "1NF only".
- Cycle (A→B→F→E→A) dikhe to us cycle ke har attribute se ek key ban sakti hai.
== sol
D kabhi RHS me nahi → har key me D.
A+ = {A, B, C} → B se {F, H} → F se {E, G} → poora A..H except D. To **AD** key.
E→A, F→E, B→F → ED, FD, BD bhi keys. Keys = {AD, BD, ED, FD}.
Prime = A, B, D, E, F; non-prime = C, G, H.

A→BC me **A→C**: A key AD ka proper subset hai aur C non-prime → **partial dependency**. To 2NF fail.

**Answer: (A) In 1NF, but not in 2NF**

Set {1,2,3,4} par reflexive ke liye (1,1), (2,2), (3,3), (4,4) — **charon** chahiye. Har relation me ye chaar dhoondho.
== concept
### Relation ke properties (set A par)
- **Reflexive**: har a ∈ A ke liye (a,a) ∈ R.
- **Irreflexive**: koi bhi (a,a) nahi.
- **Symmetric**: (a,b) ∈ R ⇒ (b,a) ∈ R.
- **Antisymmetric**: (a,b) aur (b,a) dono ⇒ a = b.
- **Transitive**: (a,b), (b,c) ⇒ (a,c).
- **Equivalence** = reflexive + symmetric + transitive. **Partial order** = reflexive + antisymmetric + transitive.

### Counting formulas (n elements)
- Total relations: 2^(n²)
- Reflexive: 2^(n² − n)
- Symmetric: 2^(n(n+1)/2)
- Antisymmetric: 2^n · 3^(n(n−1)/2)
- Reflexive + symmetric: 2^(n(n−1)/2)

### Is topic se aur kya puchha ja sakta hai
1. Is question ka (E) → reflexive + antisymmetric + transitive → **partial order** (≤ relation).
2. (D) = {(a,b) : a > b} → irreflexive, antisymmetric, transitive (strict order).
3. n = 3 par reflexive relations = 2^6 = **64**.
4. "Kaunsa symmetric hai?" → (B) {(1,1),(1,2),(2,1)} symmetric hai par reflexive nahi.
== tips
- Diagonal pairs pehle check karo — ek bhi missing to turant "not reflexive".
== sol
- (A): (3,3) nahi → ✗
- (B): (2,2)? Nahi … (3,3), (4,4) bhi nahi → ✗
- (C): (1,1), (2,2), (3,3), (4,4) sab hain → ✓
- (D): koi diagonal pair nahi → ✗ (irreflexive)
- (E): (1,1), (2,2), (3,3), (4,4) → ✓

**Answer: (D) (C) and (E) Only**
== refs
- Kenneth Rosen — Discrete Mathematics and Its Applications, Sec 9.1 (Relations and their properties).

### Declaration padhne ka niyam (right-left rule)
Naam se shuru karo, pehle right dekho (`()` ya `[]`), phir left (`*`), brackets ka priority.
- `int (*fp)(int, int);` → fp ek **pointer** hai jo aise function ko point karta hai jo 2 int le aur int de.
- `int *fp(int, int);` → fp ek **function** hai jo `int *` return karta hai.
- `int (*arr[5])(int);` → 5 function pointers ka array.
- `int (*p)[10];` → 10 int ke array ka pointer.

### Use
```
int add(int a, int b) { return a + b; }
int (*fp)(int, int) = add;   // ya &add
printf("%d", fp(2, 3));      // 5, (*fp)(2,3) bhi chalega
```
Callbacks (qsort ka comparator) isi se banta hai.

### Is topic se aur kya puchha ja sakta hai
1. `qsort(arr, n, sizeof(int), cmp)` — cmp ka type `int (*)(const void *, const void *)`.
2. `typedef int (*op)(int,int);` → phir `op f = add;`.
3. `char *(*f)(void)` → pointer to function returning char*.
== tips
- `(*naam)` = pointer; `naam(...)` bina bracket = function.
== sol
- (A) `int *func(int,int)` → function jo int* return kare.
- (B) `int (*func)(int,int)` → **function pointer** ✓.
- (C), (D) → syntax error.

**Answer: (B) int (*func) (int, int);**

- Inputs x_i, weights w_i, bias b. Net = Σ w_i x_i + b.

- **Learning (delta / perceptron rule)**: w_i ← w_i + η (t − o) x_i (t = target, o = output).
- Single-layer perceptron sirf **linearly separable** problems solve karta hai (AND, OR — par XOR nahi).

### Common activation functions
- Step, sign, **sigmoid** 1/(1+e^(−x)), **tanh**, **ReLU** max(0, x), softmax (multi-class output).

### ANN applications
Pattern recognition, image/speech recognition, NLP, forecasting, **system identification and control**, medical diagnosis.

### Is topic se aur kya puchha ja sakta hai
1. "XOR ko single perceptron kyu nahi seekh sakta?" → linearly separable nahi; hidden layer chahiye.
2. "Widrow-Hoff rule" → delta rule ka doosra naam (LMS).
3. AND gate perceptron: w1 = w2 = 1, threshold 1.5.
4. "Sigmoid ka derivative" → σ(x)(1 − σ(x)).

- (A) Activation function → (II) key component of perceptron
- (B) Learning method → (I) delta rule

**Answer: (C) (A)-(II), (B)-(I), (C)-(IV), (D)-(III)**

== concept
### Banker's algorithm (deadlock avoidance)
Data structures (n processes, m resource types):
- **Available[m]**, **Max[n][m]**, **Allocation[n][m]**, **Need[n][m] = Max − Allocation**.

**Resource-request algorithm** (P_i ki request R_i):
1. R_i ≤ Need_i? Nahi to error (max claim se zyada).
2. R_i ≤ Available? Nahi to wait.
3. Pretend allocate: Available −= R_i, Allocation_i += R_i, Need_i −= R_i.
4. **Safety algorithm** chalao: safe → grant; unsafe → rollback, P_i wait.

**Safety algorithm**: Work = Available; Finish[i] = false. Aisa i dhoondho jiska Need_i ≤ Work aur Finish false → Work += Allocation_i, Finish = true. Sab true → safe. Complexity O(m·n²).

### Is topic se aur kya puchha ja sakta hai
1. "Unsafe state = deadlock?" → nahi; unsafe me deadlock **ho sakta**.
2. Total 12 tapes, P0 (max 10, alloc 5), P1 (4, 2), P2 (9, 2) → available 3 → safe sequence <P1, P0, P2>.
3. "Banker's algorithm ka drawback" → max demand pehle pata honi chahiye, processes count fixed.
4. "Single instance per resource type ke liye" → resource-allocation graph with claim edges.
== tips
- "Must be the only one" type absolute shart — algorithm me kahin nahi.
== sol
(A), (B), (C) asli conditions hain. (D) koi requirement nahi — kai processes ek saath request kar sakte.

**Answer: (D) The process must be the only one requesting resources.**
