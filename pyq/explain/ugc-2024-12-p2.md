### Basic solution (LP)
m equations, n variables (n > m): koi bhi (n − m) variables **0** rakh ke baaki m solve karo → **basic solution**.
- Zero rakhe variables = **non-basic**, solve kiye = **basic** variables.
- Max basic solutions = **ⁿCₘ**.
- **Basic feasible solution (BFS)**: basic solution jisme sab ≥ 0.
- **Degenerate**: koi basic variable bhi 0 ho.
- Simplex method BFS se BFS pe jaata (feasible region ke **corner points**).

### Is example me
n = 3, m = 2 → ³C₂ = 3 basic solutions:
- x₃ = 0: (2, 1, 0) — feasible.
- x₂ = 0: (5, 0, −1) — basic par **infeasible** (negative).
- x₁ = 0: (0, 5/3, 2/3) — feasible.

### Is topic se aur kya puchha ja sakta hai
1. "Number of basic solutions for 3 equations, 5 variables" → ⁵C₃ = 10.
2. "Which basic solution is not feasible?" → (5, 0, −1).
3. Simplex: entering variable = most negative Cj − Zj (max problem), leaving = min ratio test.
4. LP graphical method: optimum hamesha corner point pe.
== tips
- Basic solution me exactly (n − m) zeros check karo — fastest.
== sol
- x₃ = 0: x₁ + 2x₂ = 4, 2x₁ + x₂ = 5 → x₁ = 2, x₂ = 1 → (B) ✓.
- x₂ = 0: x₁ + x₃ = 4, 2x₁ + 5x₃ = 5 → x₁ = 5, x₃ = −1 → (C) ✓.
- x₁ = 0: 2x₂ + x₃ = 4, x₂ + 5x₃ = 5 → x₂ = 5/3, x₃ = 2/3 → (D) ✓.

### Fixed-point multiplication pipeline (Wallace tree)
- 8 × 8 multiply → **8 partial products** (shifted multiplicand × bits).
- **CSA (carry-save adder)**: 3 numbers → 2 numbers (sum + carry) bina carry propagate — fast.
- Wallace tree: CSAs ki levels se 8 → 6 → 4 → 3 → 2 numbers.
- **CPA (carry-propagate adder)**: last ke 2 numbers jodkar final product (16 bits).

### Hwang ka 4-stage version
- S1: 8 partial products generate.
- S2: two levels of four CSAs (8 → 4 numbers).
- S3: two CSAs (4 → 2).
- S4: CPA (2 → 1).

### Linear vs nonlinear pipelines
- Linear: fixed function, stages ek line me.
- Nonlinear (dynamic): feedback/feedforward, reservation table, multiple functions.

### Is topic se aur kya puchha ja sakta hai
1. "CSA input/output" → 3 inputs, 2 outputs.
2. "Why CSA faster?" → carry propagation ek baar sirf end me.
3. "Number of CSA levels for 8 operands" → 4 (Wallace tree).
== tips

== sol

### Keys
- **Super key**: attributes ka set jo tuple uniquely identify kare (extra attributes allowed).

### Cache performance
- **Hit ratio h** = hits / (hits + misses); miss ratio = 1 − h.
- **Average memory access time (AMAT)** = hit time + miss rate × miss penalty.
- Hierarchical access: T = h·Tc + (1 − h)(Tc + Tm). Simultaneous: T = h·Tc + (1 − h)·Tm.
- Hit ratio pe asar: cache size, block size, **associativity**, replacement policy (LRU, FIFO, random), write policy.
- Hit ratio nikalne ke liye real programs ke **address traces** se **trace-driven simulation** ki jaati (Hwang).

### Misses ke types (3 C's)
- **Compulsory (cold)**: pehli baar block access.
- **Capacity**: cache chhoti.
- **Conflict**: mapping ki wajah se (direct-mapped/set-assoc).
(+ Coherence misses in multiprocessors.)

### Mapping
Direct (block i → line i mod m), fully associative, k-way set associative. Address = tag | index | offset.

### Is topic se aur kya puchha ja sakta hai
1. Tc = 20 ns, Tm = 200 ns, h = 0.95 (hierarchical) → 0.95·20 + 0.05·220 = 30 ns.
2. 64 KB cache, 32 B block, 4-way, 32-bit address → sets = 512 → offset 5, index 9, tag 18.
3. "Larger block size" → spatial locality badhti, par miss penalty aur pollution badhta.
== tips
- Performance question = hit ratio + access times formula.
== sol
Cache performance evaluate karne ke liye sabse common measure hit ratio (PW key).

**Answer: (A) Hit Ratio**
== refs
- M. Morris Mano — Computer System Architecture, Sec 12.6 (Cache memory: hit ratio).

### Software equation (Putnam–Myers, Pressman)
Dynamic multivariable model:
E = [ LOC × B^0.333 / P ]³ × (1 / t⁴)

### Important logical equivalences
- **Implication**: p → q ≡ ¬p ∨ q ≡ ¬q → ¬p.

- **Absorption**: p ∨ (p ∧ q) ≡ p; p ∧ (p ∨ q) ≡ p.
- p ∨ (¬p ∧ q) ≡ (p ∨ ¬p) ∧ (p ∨ q) ≡ p ∨ q (distributive).
- Distributive, associative, commutative, idempotent, double negation, identity, domination laws.
- ¬(p → q) ≡ p ∧ ¬q.
- (p → q) ∧ (p → r) ≡ p → (q ∧ r); (p → r) ∧ (q → r) ≡ (p ∨ q) → r.

### Tautology / contradiction / contingency
Tautology: hamesha true (p ∨ ¬p). Contradiction: hamesha false. Truth table ya laws se check.
